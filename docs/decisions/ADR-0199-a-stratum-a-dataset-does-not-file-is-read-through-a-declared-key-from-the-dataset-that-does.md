# ADR-0199: a stratum a dataset does not file is read through a declared key from the dataset that does

**Date:** 2026-10-24. **Status:** accepted. **Request:** PegaSUS counts a dataset's events by residence, sex and age, read from `stratum` roles; `gateway._strata('SIHSUS-SP', 'procedure')` raised "no age stratum", so no study could read SIH-SP.

**Context.** SIH-SP files the procedure lines of an admission with the patient's municipality (`SP_M_PAC`) and no sex or age. They are on the admission, SIH-RD (`SEXO`; `IDADE_anos`, made from `IDADE` and `COD_IDADE`), and the two share the AIH (`SP_NAIH` = `N_AIH`, `curation/joins.yml`). RD is nearly one row per AIH, and every repeat is a long-stay part (IDENT 5) of the same admission: Acre 2023, 20 AIHs and 53 extra rows (0.09%); SP 2023-01, 56 of 210,161 AIHs. A join of the two by rows multiplies SP's lines by RD's repeats, and a count over it looks like a count of procedures.

**Decision.**
1. **Declaration.** A column the dataset does not file is declared in its role file with `through: {key: AIH, dataset: SIH-RD}` (`semantics/column_roles`): the column of the same name of that dataset, on the row sharing this record's key. It states the same role and kind as the source's (checked on load: a sex is a sex), the source files it itself (no chain), and the key of `joins.yml` has both datasets as members, so the columns that join are declared once, there. SIH-SP declares `SEXO` (`patient.sex`) and `IDADE_anos` (`patient.age_years`) as strata, 2008-2026, the years of its residence. `roles()` returns the `through` of such a row.
2. **Which row stands for a repeated key** is declared on the source's member of the key, not in code: `principal: {column: IDENT, codes: ["1"]}` on SIH.RD's `N_AIH` in `joins.yml`. The key's row is the first one with a principal code, else the first in file order.
3. **Reading** (`semantics/through.py`, called by `query`). A through column is read when selected by name; a full-width read of SP is not a request for RD's. `query` takes the through columns out of the request to the dataset's own files, adds the key column, and after the period filter attaches the columns from `query(source, same period, same geography)` read in the canonical form (the presentation is applied once, last). The event readers `read_events` and `count_events` call `query`, so a count of SP's procedures by sex and age is one request. Publications select; they never filter records: RD is read for the months and states SP's request names.
4. **No multiplication, nothing silent.** The source row is looked up by key (one row per key, taken, never joined), so SP's rows are the rows delivered, and the count is checked before and after (a difference raises). Keys match exactly: no padding or truncation, only the whitespace of a fixed-width field. A row whose key finds no source row has the column null (never a guess, never dropped); the table's `pegasus.through` metadata and `QueryReport.through` say, per key and source, the rows and keys matched and not, the source's rows, repeated keys and keys whose rows disagree on the columns read; a `ThroughKeyWarning` names the unmatched share. The engine then reads those rows as unallocated by 'sex' or 'age', as it reads any record with none.
5. A condition on roles cannot test a through column (the records are selected before it exists); it raises and says to condition on the source.

**Evidence.** `docs/evaluation/2026-10-24-sp-sex-and-age-through-the-aih.md`: Acre 2023-01, SP's 46,933 rows in and out; all 4,164 SP AIHs in RD's 4,165 rows (one AIH repeats, types 1 and 5, same sex and age); on the matched admissions SP and RD agree on residence, principal diagnosis, admission date and facility for 4,164 of 4,164, so the key pairs one admission (also AC 2008-06, 2013-06 and RR 2025-06, every AIH); every SP AIH is in the same period's RD in nine more reads, Acre and Roraima 2008 to 2025; removing 50 AIHs from RD's rows makes exactly their 523 SP rows null and reported, the rest unchanged (386, 317 and 196 rows in the three other months, likewise); `count_events` sums to the 83,263 procedures of `SP_QT_PROC`; the engine's `_strata` returns residence, sex and age and `event_counts` counts them by sex and age.

**Not done.** SP's race (RD's `RACA_COR`) is not declared. RD is read for the same period only: an AIH whose RD row is filed in another month would be unmatched (none was in the sample, and the report would say so). A through column of a dataset whose event type compares whole rows (`duplicates.except`) is refused. The shared "structurally absent" warning of RD's derived `IDADE_anos` now also appears in a read of SP's.

**What would overturn it.** A period in which SP's AIHs are not in the same month's RD (the unmatched share would say so, and the key would need the neighbouring months); a source whose repeated keys disagree on the column read, which the report counts; a use that needs a through column in a condition.
