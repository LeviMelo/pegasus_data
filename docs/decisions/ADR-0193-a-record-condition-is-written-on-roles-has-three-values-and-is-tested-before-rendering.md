# ADR-0193: a record condition is written on roles, has three values, and is tested before anything is rendered

**Date:** 2026-10-15. **Status:** accepted. **Origin:** PegaSUS's topics were code sets (ICD-10, SINAN agravos), and many standard ones are a condition on a record's typed fields: low birth weight (SINASC `PESO` under 2,500 g), preterm birth, caesarean delivery, adolescent mothers, infant and neonatal deaths (SIM `IDADE` under one year, under 28 days), deaths at home, admissions of the elderly. `rows=` filters by code prefix and cannot say them.

**Context.** The same property is another column in another layout (gestation is `GESTACAO`, a band, before 2010 and `SEMAGESTAC`, weeks, from then; two columns carry the baby's race in 2012-2013), so a condition written on column names is wrong across years. A weight is a number only where it is a measurement: `PESO` files `0000` and `9999` for "not recorded" and `9000`-`9998` that no one weighed; "under 2,500" read from the text counts 0 g. The age of a death is not a column: SIM packs a unit into `IDADE` (`201` is one day, `301` one month) and the query derives `IDADE_anos` once (ADR-0070).

**Decision.**
- **Grammar** (`pegasus_data/conditions.py`): a list of clauses ANDed, each `{"role": "birth.weight", "op": "<", "value": 2500}`, or the operator as the key, `{"role": "birth.delivery", "in": ["2"]}`. `op`: `<  <=  >  >=  ==  in  not in`; `unit` (days, weeks, months, years) restates a time for a role measured in years (`{"role": "deceased.age_years", "op": "<", "value": 28, "unit": "days"}`). Unknown keys, an empty list, a number against a code, an order between codes, a missing code named as a value, a role the dataset does not declare (with the closest), a column of kind date or identifier, and a measure whose not-recorded values are undeclared all raise before any file moves.
- **Roles, per year.** A clause resolves, for each year read, to the column of `curation/roles/<dataset>.yml` that carries the role (`role` or `also`) in that year; two columns for one role in one year raise; none leaves the clause unevaluable for that year.
- **Three values.** A clause is true, false or unknown; a record is false if any clause is false, true if all are, else unknown (Kleene). A number is read from the text as filed (decimal comma accepted); the role's `missing` codes and values outside its `domain` are unknown, as is anything that is not a number. A category is matched as filed, exact width, never padded; blank and `missing` codes are unknown (a delivery filed `9` is not "not a caesarean"). A derived age is unknown where `_age` finds none. Only false records leave the result.
- **Where.** Raw columns are tested in the lake's scan (the records not false are read: the same arithmetic builds the Arrow predicate and tests the records), a derived one after the read, all before anything is rendered, so a label never takes the place of the code; the fetch path tests the decoded table the same way. The age is `view.derived_age_years`, which calls the converter `_apply_derived` calls (`_age.years_column`): never re-derived. A time restated by `unit` uses `_age`'s constants (`28 * _DAY`, bit for bit), so a 28-day age is exactly where the neonatal period ends.
- **Reported, not hidden.** `query(condition=)`: the table, `report.condition` and the table's metadata (`conditions.condition_report`: `clauses`, `satisfied`, `unknown`) say how many records the condition could not decide. `count_events(condition=)` and `read_events(condition=)` take the same list; `count_events` adds a column `unknown` (events, weights counted, by the same `by` groups); a condition selects the records the event rule (duplicates, status, consolidation) then applies to, as `rows=` does. `Condition.key()` is the canonical text of a condition, for a caller that caches a result under it; nothing in pegasus_data caches a read.
- The roles in use: `birth.weight`, `birth.delivery`, `birth.gestation_weeks`, `birth.gestation_band`, `mother.age` (SINASC); `deceased.age_years`, `death.place` (SIM); `patient.age_years` (SIH).

**Not done.** `OR` and `not` between clauses; a condition on an extract's digest (`extract_dir` is keyed by prefix filters; `read_events(records=)` tests an extract's records in place); the CLI and `serve/`; a role whose `missing` is undeclared is refused, not guessed. SIM's `IDADE` `300` ("0 months", one 2019 death) decodes as 0.0 years and counts as neonatal where TabNet bins it 28-364 days (OQ 85).

**What would overturn it.** A role table that gives one role two columns in the same years (the condition would need to name one); a published definition of an indicator that counts the unknown as a failure (it is then the consumer's, with the `unknown` column in hand).
