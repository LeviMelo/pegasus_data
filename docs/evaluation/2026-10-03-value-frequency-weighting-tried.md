# Value-specific chance agreement: tried, measured, removed (kept here for the record)

**Date:** 2026-10-03.

**Regime:**
- branch `linkage`; data home `C:\Users\Galaxy\pegasus_linkage`;
- `scripts/link_scope_test.py sih_deaths_to_sim 2022 SE RR SP`, its first run,
  with this code in place.

**Why it was tried.** docs/plans/linkage-theory.md §3.1 proposed that two
records agreeing on a value be weighed by how common that value is:
- agreement on a birth date few people share, or a small municipality, is
  stronger evidence than agreement on a common one;
- with the partner side read nationally, the frequencies would be national
  whatever the slice (scope invariance, §3.2).

This is the classic value-specific (frequency-based) u of record linkage.

**What it did.** For comparisons of kind date, facility, municipality and code
(without a conditioning role), the "equal" level's bits were replaced, pair by
pair, by `log2(m_equal / f_R(v))`. Here `f_R(v)` is the share of right-side
records holding the agreed value `v`. The other levels kept their global u.

The code, as it stood in `linkage/probabilistic.py` (never committed; removed
the same day):

```python
#: Comparison kinds whose "equal" level is weighed by the agreed value's
#: frequency on the right side.
FREQUENCY_KINDS = ("date", "facility", "municipality", "code")


def _frequencies(con: duckdb.DuckDBPyConnection, compare) -> dict[int, tuple[pa.Array, np.ndarray]]:
    """Per comparison: the right side's values and log2 of their share among filled records."""
    out = {}
    for i, c in enumerate(compare):
        if c.kind not in FREQUENCY_KINDS or c.given:
            continue
        col = _q(c.right)
        t = con.execute(f"""SELECT {col} AS v, count(*) AS n FROM (SELECT DISTINCT ON (_id) * FROM R)
                            WHERE {col} IS NOT NULL GROUP BY 1""").fetch_arrow_table()
        if not t.num_rows:
            continue
        n = t.column("n").to_numpy().astype(float)
        out[i] = (t.column("v").combine_chunks(), np.log2(n / n.sum()))
    return out


def _equal_bits_by_value(fm, lv, right_values, freq, bits):
    """Replace the "equal" level's bits by log2(m_equal / share of the agreed value)."""
    eq = lv == "equal"
    if not eq.any() or "equal" not in fm.m:
        return bits
    values, logf = freq
    idx = pc.fill_null(pc.index_in(right_values, value_set=values), -1).to_numpy(zero_copy_only=False)
    known = eq & (idx >= 0)
    m_eq = max(fm.m["equal"], 0.5 / max(fm.anchors, 1))
    out = bits.copy()
    out[known] = np.log2(m_eq) - logf[idx[known]]
    return out

```

## Result

National `sih_deaths_to_sim`, 2022:

| | pairs | FDR upper 95% |
|---|---|---|
| without (stored run, and the rerun after removal) | 545,135 | 0.24% |
| with value-specific u | 539,046 | 1.03% |

Fewer pairs at four times the false-link rate: worse on both counts. The rerun
without it reproduced 545,135 pairs and 0.24% exactly.

## Why it failed

**Candidates are generated by blocking.** The blocks are birth date + sex,
and death day + hospital. Inside a block, agreement on the block's fields is
guaranteed, so for those fields the relevant chance agreement is conditional
on the block, not the marginal frequency.

- **Small hospitals.** Weighting a small hospital's rarity gave large bits to
  placebo pairs that were only candidates because they shared that hospital
  and day. The placebo counted them, and the threshold moved up past real
  pairs.
- **The evidence was counted twice:** once by the block that selected the
  pair, once by the weight.

**The same mechanism reappeared twice in later work the same day:**
- **Inherited AIH.** The u of a new evidence-only comparison came from random
  pairs, which almost never have nearby AIHs. Among same-hospital, same-day
  candidates nearby AIHs occur about 3% of the time by chance, so "within 100"
  earned +15 bits.
- **Slices.** A slice's u from its own random pairs (a state's records
  against the nation) was not the nation's chance rate.

**The lesson the engine keeps.** u must be estimated on the population the
scores are compared within:
- the candidate pairs, or the placebo, for comparisons the blocks condition
  on;
- the national population for a slice that decides with the national
  threshold.

## What would make it work, if revisited

Frequency weighting only for fields **not used in any block** of the spec, and
u per value estimated **within blocks**, from the placebo candidates rather
than from the marginal frequency.

Not tried: the gain is uncertain, and the placebo-based u for evidence-only
comparisons covers the case that mattered.
