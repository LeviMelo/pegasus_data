# Filtered extracts: a dataset larger than the lake (2026-10-11)

**Why.** SIA-PA 2010–2025 is 175 GB of DBC files, and SIA-BI 156 GB. The data root has under 180 GB free. The
toxoplasmosis study needs only SIA-PA's toxoplasma serology (SIGTAP 0202030768 IgG, 0202030873 IgM, 0202110150 IgM in
the heel-prick test, 0213010577 ELISA IgG) and its records coded B58, O98.6 or P37.1.

**What.** `pegasus_data.extract` (`build_extract`, `pegasus-data extract`) reads a dataset's published files one at a
time, in a window of three: fetch, decode, keep every record that any filter (column → code prefixes) matches, write
it, and release the blob. Its manifest names each file's rows read and kept, and any that failed. `extract_table` serves
a code set only for years the extract holds whole. `count_events(records=)` counts an extract's records.

**Known answer.** SIA-PA, Rio Grande do Sul, 2018, procedure filter (`ctl/extract_test.py`, data root
`pegasus_core_data`):
- 12 files, 30,981,518 records read, 94,630 kept, 334 s.
- Santa Maria (431690), quantity approved per month:

  | month | Jan | Feb | Mar | Apr | May |
  |---|---|---|---|---|---|
  | 2018 | 1,162 | 1,126 | 1,054 | 3,107 | 4,594 |

  The earlier direct read of the same records gave about 1,100 a month in 2017, 3,075 in April and 4,613 in May. The
  outbreak's serology is there.
- With the topic's ICD-10 codes on PA_CIDPRI as a second filter: 94,834 kept.
- Read for 2018 as a whole, the RS-only extract refuses ("324 files unread").

**Also.** SNGPC's 2014–2018 months are not all latin-1, which `intake.yml` declares. A month whose declared encoding
fails is now read as "mixed": each line's valid UTF-8 is kept and stray bytes are read as cp1252. The unit records it.

**One release rule (same day).** The extract deleted each file's blob by a rule of its own, which trusted partitions
without verifying them. Lake builds kept every file beside its Parquet, so each downloaded gigabyte cost disk twice.
Now one rule, `BlobStore.prune_verified(paths=, held=)`, serves:
- the extract, which holds the files it read;
- `build_lake(release=True)`, whose verified partitions hold their files (PegaSUS's `gateway.ensure_lake` asks for it);
- `prune`, over everything.

A scoped release takes under a second: SIA-AN 2009–2014, 1,825 files and 0.37 GB, in 0.6 s. `prune` over the data
root freed 10.4 GB of files the lake already held (16,418 kept); the disk had fallen to 19 GB free.
