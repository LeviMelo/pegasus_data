# Levels labelled as a query labels them (2026-10-11)

**Scenario.** PegaSUS's toxoplasmosis report named its group findings by raw column and code (`EVOLUCAO=1`). Naming
them needs a field's code → label without a table of records, which `view.codelist_levels` gave the capability
descriptor. Checked against a labelled `pg.query` of the same dataset, the reading the user sees. Data root
`pegasus_core_data`; branch `pegasus-core-fixes`.

**Found.** `codelist_levels` merged every table bound to the field, first wins, and the descriptor passed no family,
so the form's own dictionary was out of reach. Wrong labels, against the query's:

| dataset, field, code | `codelist_levels` | `query` |
|---|---|---|
| SINAN-TOXG EVOLUCAO 2 | Óbito por meningite | Óbito pelo agravo notificado |
| SINAN-ACBI EVOLUCAO 3 (served to clients) | Óbito por LTA | Alta paciente fonte negativo |
| SINAN-ACBI EVOLUCAO 1, 2 | Cura, Abandono | Alta com conversão sorológica, Alta sem conversão sorológica |

**Change.** `codelist_levels` renders the codes as a one-column table through `render_table`, so the same ladder
(`label_bindings.decide`: the form's dictionary, curated tables, measured weighing) chooses the table; the descriptor
passes the artifact's family. New verb `pg.levels(dataset, field, codes)`. After it, all four built artifacts'
dimensions match the query (ACBI's seven outcomes, SIM, SIH, CNES).

**Left.** Weighing reads the codes it is given. A caller passing a subset can choose another table: TOXC CRITERIO
{1, 2, 9} reads Laboratorial and Clínico-epidemiológico, but {1, 2, 7, 9} reads meningitis's criteria (Cultura, CIE).
Callers pass every value the column holds. PegaSUS's `gateway.value_labels` does.
